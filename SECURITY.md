# Безопасность SSH-Hardener

Автор программы: **@victoryur**. Текущая ветка содержит предварительную реализацию, не прошедшую полную VM-матрицу. Политика не обещает защиту от всех способов потери доступа.

## Модель угроз

Приложение работает от имени пользователя Windows и использует административные полномочия на выбранном Linux-сервере. Защищаемые активы: учётные данные, приватные ключи, идентичность сервера, текущий путь управления, серверные конфиги, правила фильтрации и журнал транзакции.

Учитываются MITM при первом/повторном подключении, command injection из UI и серверных данных, потеря сети, падение клиента, ошибка sshd, неверный firewall и неполная аутентификация. Host key проверяется на каждом соединении; первый TOFU требует независимой сверки отпечатка. Смена порта не должна обнулять доверие.

Скомпрометированные root на сервере, пользователь Windows, ядро/гипервизор, вредоносный пакетный менеджер и физический отказ за границами доверия. Сервер с уже захваченным root способен подделать аудит и результат проверки. Защита DPAPI привязана к текущему пользователю и не спасает от кода, запущенного с его правами.

## Транзакция

Применение допускается лишь для распознанной и поддерживаемой конфигурации. План фиксирует входные данные. Перед изменением доступа необходим независимый серверный rollback с проверенным arming. Старый и новый порты сохраняются до проверки. Commit требует свежей сессии с новым ключом, закреплённым host key и нужными привилегиями после окончательных изменений.

Серверные commit/rollback должны исключать гонку друг с другом, использовать root-owned состояние и блокировку. Таймер не устраняет необходимость консоли провайдера. Возврат к старой конфигурации после commit — потенциально опасная операция и не должен обещаться как универсальное «отменить всё».

Нельзя восстанавливать весь firewall snapshot поверх сторонних правил или удалять домашний каталог созданного пользователя. Нельзя считать установку пакетов полностью обратимой. Неизвестные socket activation, Include/Match, policy routing, контейнерные сети и несколько менеджеров правил блокируют автоматическую мутацию, пока нет проверенного провайдера.

## Секреты

Пароли/passphrase не должны попадать в аргументы процессов, предпросмотр команд, журналы или отчёты. SSH-транспорт должен передавать sudo-секрет отдельно по stdin без эха. Управляемые строки могут сохранять копии в памяти; абсолютное отсутствие секретов в дампах не гарантируется.

Приватный ключ намеренно сохраняется только в явно выбранный пользователем файл. Зашифрованный PKCS#8 PEM не следует называть OpenSSH-v1. Локальные настройки и exported reports не являются хранилищем приватных ключей. Подтверждённые host public keys не секретны, но их целостность критична.

Файловые ACL, DPAPI и ограниченный срок хранения защищают локальные данные в пределах модели доверия. Серверные бэкапы не должны экспортировать host private keys. В отчётах необходимо экранировать HTML и shell; CSV — защищать от formula injection.

## Известные ограничения

- Полная проверка systemd/firewall/SELinux/reboot требует VM. Docker transport test её не заменяет.
- Внешние security groups не управляются без отдельной интеграции.
- Публичный ключ без доступного приватного не доказывает работоспособность нового входа.
- NOPASSWD ALL даёт полный root-эквивалент и требует явного решения администратора.
- Изменение SSH-порта не исправляет уязвимости ОС/OpenSSH.
- Клиент исключает устаревшие SHA-1/DSA/CBC-варианты и не возвращает их автоматически ради старого сервера; совместимость с RSA SHA-2 сохраняется.
- Отсутствие подписывающего сертификата означает неподписанную сборку; наличие CI не делает её доверенной поставкой.

## Сообщение об уязвимости

Не публикуйте рабочие пароли, ключи или данные сервера. Используйте приватное сообщение автору @victoryur по уже известному вам каналу; адрес контакта намеренно не выдуман. Если в репозитории включён GitHub Private Vulnerability Reporting, используйте вкладку Security → Report a vulnerability. В обычном issue оставляйте только безопасное описание без эксплуатационных секретов.
